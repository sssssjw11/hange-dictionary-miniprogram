## 复现命令

```powershell
npm ci --ignore-scripts
npm run build:codec
npm run build:data
npm run check
npm test
python -m unittest discover -s tests -p 'test_*.py' -v

# 启动本地服务后，在另一终端启用真实查询联调
$env:HANGE_TEST_API='http://127.0.0.1:18748'
npm test

# 已安装可选引擎和模型时
$env:HANGE_TEST_MEDIA='1'
python tests/test_features.py

# 已生成自己的离线包时，逐份核对全部正文
node scripts/verify_offline_corpus.js
```

公开 CI 会跳过没有私有词库、没有模型的联调项，但仍运行通用存储、转换、输入契约、分页和模板检查。不会把跳过项计作真机成功。

## 微信模拟器与手机范围

开发工具 2.02.2609240、官方 skill CLI 0.3.11；用户完成连接授权和工具登录后，在导入界面使用工具提供的测试号启动。公开 `touristappid` 保留为占位，专用测试身份只在本机调试工程中保存。没有上传或发布。

原生运行证据包括完整分卷安装、刷新后离线状态、参考截图中的英文词、中文“人际关系”反查及直接释义排序。`run` 的 30 块正文通过真实下一页按钮遍历 8 页，正文文字合计 21,273 字符。词条排版另核对中英标签、正常英文换行及完整中文释义；不把原文领域标签当作历史中的词义。

使用原生微信文件系统创建的临时阅读材料包含中文、重音字符和 emoji；跨页标注 2000 字符、书签、分组、例句和自定义词表可读取。v3 备份合并再导入后记录保持一致，测试完恢复原有学习存储，只移除本次创建的文件；离线词库仍保留。文件分享、麦克风、相机和系统权限没有被自动确认。

以下仍需要对应设备和条件：

1. iOS / Android 的完整分卷选择、空间预算、中断恢复、重启及持续使用。
2. 相机、相册、原生编辑/裁剪、麦克风授权、真实录音、音频播放与切后台。
3. 微信备份分享、从微信文件再次导入、软键盘、安全区和各机型尺寸。
4. 系统主题变化、阅读字号、平板和微信桌面版。
5. 自己的有效 AppID、HTTPS、合法域名下的真机请求、上传与下载。

真实本地 OCR / TTS / ASR 服务检查、微信模拟器检查和 Chromium 布局投影分别记录。当前没有模型服务，因此 AI 和全文翻译仍为待配置；原厂云内容、题库、MDD 及 Android 系统能力的边界见 [功能对照](FEATURE_PARITY.md)。
